Text Representation: From Word Counts to Semantic Embeddings

This workbench explains how NLP systems convert text into numbers. We begin with simple count-based representations, then move to word embeddings, contextual embeddings, sentence embeddings, and finally semantic search.

Identity→ Counts→ Weights→ Word Meaning→ Context→ Sentence Meaning→ Semantic Search
How to use this page: every method now begins with a tiny document or corpus. Students first see the raw text, then tokens/vocabulary/context, then the numeric calculation, and finally the resulting vector or score. Learned neural methods are clearly labeled when the hand arithmetic is a simplified teaching approximation.

Why representation matters

Most machine-learning algorithms work with numbers, not raw text. A text representation is the numeric form we give to words, sentences, or documents so that an algorithm can compare them and learn patterns.

Count-based

We count which words appear and how often.

2010

Examples: Bag-of-Words, TF-IDF.

Word embeddings

Words become dense vectors learned from context.

.21-.40.78.11

Examples: Word2Vec, GloVe, FastText.

Sentence embeddings

Entire sentences or documents become vectors.

🔐 ↔ 🔑

Useful for similarity and semantic search.

Remember: A better representation can make a simple model much more useful because the model sees better features.

1. One-Hot Encoding

One-hot encoding is one of the simplest ways to represent categories or words. Each possible item gets its own position in a vector.

How it works

Suppose we have four emotion categories: happy, sad, excited, and sick. We create a vector with four positions. Only one position is turned on at a time.

Interactive emoji example

Click an emoji to see its one-hot vector.

Sad
Excited
Sick

Selected vector

😄 Happy

Interpretation: the vector does not mean “20% happy” or “80% sad.” It only tells us which category is active.

Strength

One-hot encoding is simple and easy to interpret.

Limitation

It does not capture similarity. For example, “happy” and “excited” are related, but their vectors are just as different as “happy” and “sick.”

Python: one-hot vectors
labels = ["happy", "sad", "excited", "sick"]

happy = [1, 0, 0, 0]
sad   = [0, 1, 0, 0]

print(happy)
print(sad)

Final idea: one-hot encoding represents each word separately. The document becomes a sequence of vectors, but the vectors themselves do not show semantic similarity.
What students should remember: one-hot encoding represents identity, not meaning.

2. Bag-of-Words

Bag-of-Words represents a document using word counts. It ignores grammar and word order and focuses only on which words appear.

Step 1: Build a vocabulary

From the sentences below, the useful vocabulary might be: cat, dog, runs, sleeps.

Documents

🐱 “the cat runs”

🐶 “the dog sleeps”

🐱 “the cat sleeps”

Vocabulary

catdogrunssleeps

Step 2: Count words

catdogrunssleeps
Doc 11010
Doc 20101
Doc 31001

Why is it called a “bag”?

Because the model behaves as if the words were placed into a bag and mixed together. The original order is not preserved.

Important limitation: “dog bites man” and “man bites dog” contain the same words, so a simple Bag-of-Words representation can look identical even though the meaning changes.
Python: CountVectorizer
from sklearn.feature_extraction.text import CountVectorizer

docs = [
    "the cat runs",
    "the dog sleeps",
    "the cat sleeps"
]

vectorizer = CountVectorizer(stop_words="english")
X = vectorizer.fit_transform(docs)

print(vectorizer.get_feature_names_out())
print(X.toarray())

Final result: each document is now a numeric vector of word counts.
What students should remember: Bag-of-Words is simple and useful, but it captures counts rather than meaning.

3. TF-IDF

TF-IDF improves on raw counts by reducing the influence of words that appear everywhere and increasing the importance of words that help distinguish one document from another.

TF: Term Frequency

How often does a term appear in a document?

IDF: Inverse Document Frequency

How unusual or distinctive is that term across the collection?

TF-IDF(term, document) = TF(term, document) × IDF(term)

the

░░░░

Appears everywhere → low information.

model

▓▓▓░

Useful in some documents → medium/high weight.

transformer

████

Distinctive term → higher weight.

Why TF-IDF is useful

It is a strong baseline for text classification, document similarity, and search. It is often surprisingly effective, especially when vocabulary overlap is meaningful.

Main limitation

TF-IDF does not know that “doctor” and “physician” are semantically related unless those words appear together in useful ways elsewhere.

Python: TfidfVectorizer
from sklearn.feature_extraction.text import TfidfVectorizer

vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(docs)

print(vectorizer.get_feature_names_out())
print(X.toarray().round(2))
Worked Example — Start with Documents and Calculate TF-IDF Step by Step

Documents:

D1 = "cat cat runs"
D2 = "cat sleeps"
D3 = "dog sleeps"
1
Tokenize the documents.
D1 → [cat, cat, runs]
D2 → [cat, sleeps]
D3 → [dog, sleeps]
2
Build the vocabulary.
Vocabulary = [cat, dog, runs, sleeps]
3
Calculate term frequency (TF) inside each document.

For this classroom example:

TF = word count / number of words in the document

D1 has 3 words:

TF(cat, D1) = 2 / 3 = 0.667
TF(dog, D1) = 0 / 3 = 0
TF(runs, D1) = 1 / 3 = 0.333
TF(sleeps, D1) = 0 / 3 = 0

D2 has 2 words:

TF(cat, D2) = 1 / 2 = 0.500
TF(sleeps, D2) = 1 / 2 = 0.500

D3 has 2 words:

TF(dog, D3) = 1 / 2 = 0.500
TF(sleeps, D3) = 1 / 2 = 0.500
4
Calculate document frequency (DF).

DF tells us how many documents contain each word at least once.

DF(cat) = 2 → appears in D1 and D2
DF(dog) = 1 → appears only in D3
DF(runs) = 1 → appears only in D1
DF(sleeps) = 2 → appears in D2 and D3
5
Calculate IDF.

We have N = 3 documents. For this hand calculation:

IDF(term) = ln(N / DF)
IDF(cat) = ln(3/2) ≈ 0.405
IDF(dog) = ln(3/1) ≈ 1.099
IDF(runs) = ln(3/1) ≈ 1.099
IDF(sleeps) = ln(3/2) ≈ 0.405

The rarer words dog and runs receive larger IDF values.

6
Calculate TF-IDF for D1.
TF-IDF = TF × IDF
cat: 0.667 × 0.405 ≈ 0.270
dog: 0 × 1.099 = 0
runs: 0.333 × 1.099 ≈ 0.366
sleeps: 0 × 0.405 = 0
D1 TF-IDF vector ≈ [0.270, 0, 0.366, 0]
7
Calculate TF-IDF for D2 and D3.
D2:
cat = 0.500 × 0.405 ≈ 0.203
sleeps = 0.500 × 0.405 ≈ 0.203
D2 ≈ [0.203, 0, 0, 0.203]
D3:
dog = 0.500 × 1.099 ≈ 0.549
sleeps = 0.500 × 0.405 ≈ 0.203
D3 ≈ [0, 0.549, 0, 0.203]
8
Interpret the result.

In D1, runs receives a larger weight than cat even though “cat” occurs more often. Why? Because “runs” is rarer across the collection, so it carries more distinguishing information.

Final TF-IDF vectors:
D1 ≈ [0.270, 0, 0.366, 0]
D2 ≈ [0.203, 0, 0, 0.203]
D3 ≈ [0, 0.549, 0, 0.203]
Important: scikit-learn uses smoothing and normalization by default, so its exact numbers will differ. This hand calculation uses a simpler formula so students can see the core logic clearly.
What students should remember: TF-IDF is still based on vocabulary, but it gives better weights than raw counts.

4. Co-occurrence and Distributional Meaning

A key idea behind many embedding methods is that words appearing in similar contexts often have related meanings.

Simple intuition: if “doctor” and “physician” frequently appear near words such as patient, hospital, treatment, and clinic, their contexts start to look similar.

Example co-occurrence matrix

patienthospitalclinicstudent
doctor8640
physician7560
teacher0009

The rows for “doctor” and “physician” look similar, while “teacher” looks different. That similarity in context is a clue about meaning.

Mini corpus:

S1 = "doctor treats patient"
S2 = "doctor helps patient"

Use a context window of 1 word on each side.

1
Tokenize.
S1 → [doctor, treats, patient]
S2 → [doctor, helps, patient]
2
Find neighbors in S1.
doctor ↔ treats
treats ↔ doctor
treats ↔ patient
patient ↔ treats
3
Find neighbors in S2.
doctor ↔ helps
helps ↔ doctor
helps ↔ patient
patient ↔ helps
4
Add the counts.
doctor treats patient helps
doctor 0 1 0 1
treats 1 0 1 0
patient 0 1 0 1
helps 1 0 1 0
5
Interpret the rows.

“doctor” appears near “treats” and “helps”. “patient” also appears near “treats” and “helps”. Their context patterns therefore have some similarity.

Main idea: a co-occurrence matrix turns surrounding-word patterns into numbers.
What students should remember: meaning can be learned indirectly from patterns of usage.

5. Word2Vec

Word2Vec learns dense vectors for words by training on local context. Instead of manually defining meaning, the model learns useful relationships from how words appear near one another.

CBOW vs. Skip-gram

CBOW

CBOW uses surrounding context words to predict the center word. It asks: “Given the words around this position, what word probably belongs here?”

Skip-gram

Skip-gram does the reverse. It uses a center word to predict nearby context words.

For beginners, the most important idea is the prediction direction. You do not need to implement the neural-network math by hand to understand the concept.

Semantic vector space

After training, related words may appear closer together in vector space.

👑 king 👸 queen 🐶 dog 🐱 cat 🚗 car 🚚 truck 🍎 apple
Python: Word2Vec with Gensim
from gensim.models import Word2Vec

sentences = [
    ["doctor", "treats", "patient"],
    ["physician", "helps", "patient"],
    ["nurse", "cares", "patient"]
]

model = Word2Vec(
    sentences,
    vector_size=50,
    window=2,
    min_count=1,
    sg=1   # 1 = Skip-gram, 0 = CBOW
)

print(model.wv.most_similar("doctor"))
Worked Example — Start with a Corpus and Follow One Word2Vec Training Step

Mini corpus:

S1 = "doctor treats patient"
S2 = "doctor helps patient"

Use a context window of 1.

1
Create Skip-gram training pairs.

Center word → nearby context word:

doctor → treats
treats → doctor
treats → patient
patient → treats

doctor → helps
helps → doctor
helps → patient
patient → helps
2
See the CBOW version of the same idea.

For the sentence “doctor treats patient”:

CBOW input: [doctor, patient]
CBOW target: treats

For Skip-gram:

Skip-gram center: treats
Skip-gram targets: doctor, patient
The next arithmetic is a tiny forward-pass example. Real Word2Vec learns vector values through many repeated updates over a much larger corpus.

Take one Skip-gram pair:

center = doctor → correct context = treats

Assume the current 2D vectors are:

input(doctor) = [1.0, 0.5]

output(treats) = [0.9, 0.4]
output(patient) = [0.6, 0.5]
output(car) = [-0.3, 0.8]
3
Calculate dot-product scores.
score(treats) = (1.0×0.9) + (0.5×0.4) = 1.10
score(patient) = (1.0×0.6) + (0.5×0.5) = 0.85
score(car) = (1.0×-0.3) + (0.5×0.8) = 0.10
4
Convert scores to softmax probabilities.
e^1.10 ≈ 3.004
e^0.85 ≈ 2.340
e^0.10 ≈ 1.105
total ≈ 6.449
P(treats | doctor) ≈ 3.004 / 6.449 ≈ 0.466
P(patient | doctor) ≈ 2.340 / 6.449 ≈ 0.363
P(car | doctor) ≈ 1.105 / 6.449 ≈ 0.171
5
Calculate the loss for the correct context word.
loss = -ln(P(treats | doctor))
= -ln(0.466)
≈ 0.763
6
Update the vectors.

Gradient descent changes the vectors so the correct pair “doctor → treats” receives a higher probability next time. Repeating this over many examples gradually organizes the embedding space.

Main idea: Word2Vec starts from real word-context pairs in the corpus and learns vectors by repeatedly improving its context predictions.
What students should remember: Word2Vec learns word meaning from local context patterns.

6. GloVe

GloVe stands for Global Vectors. It learns word vectors from global word co-occurrence statistics rather than only local prediction tasks.

Word2Vec

Focuses on predicting local context relationships.

GloVe

Uses large-scale global co-occurrence patterns.

In practice, students often use pretrained GloVe vectors instead of training them from scratch.

Python: pretrained GloVe
import gensim.downloader as api

glove = api.load("glove-wiki-gigaword-50")

print(glove.most_similar("doctor", topn=5))
print(glove.similarity("doctor", "physician"))
Worked Example — Start with a Corpus and Follow One GloVe Loss Calculation

Mini corpus:

S1 = "doctor treats patient"
S2 = "doctor treats patient"
S3 = "doctor helps patient"

Use a context window of 1.

1
Count co-occurrences.
X(doctor, treats) = 2
X(doctor, helps) = 1
X(treats, patient) = 2
X(helps, patient) = 1
2
Choose one pair to train on.
doctor ↔ treats has count X = 2
3
Take the logarithm of the co-occurrence count.
ln(2) ≈ 0.693
Real GloVe uses two word-vector sets, bias terms, and a weighting function. We keep one loss term small here so the calculation is visible.
4
Suppose the current model predicts 0.50 for this pair.
prediction = 0.50
5
Calculate the residual.
residual = prediction - log(count)
= 0.50 - 0.693
= -0.193
6
Square the residual for a simplified loss term.
loss ≈ (-0.193)^2
≈ 0.037
7
Update the word vectors and biases.

Training adjusts them so the predicted value moves closer to the logarithm of the observed co-occurrence count.

Main idea: GloVe begins with a corpus-wide co-occurrence matrix and learns vectors that reproduce those global statistical relationships.
What students should remember: GloVe is a dense word-embedding method built from global co-occurrence information.

7. FastText

FastText improves word representations by using character-level subword information.

For example, the word teaching can be broken into smaller pieces:

teaching
<teteaeac achchihin ingng>

Why this helps

  • Related word forms can share information.
  • Morphology becomes easier to capture.
  • The model can sometimes build vectors for words it did not see exactly during training.
Python: FastText
from gensim.models import FastText

sentences = [
    ["teach", "teacher", "teaching"],
    ["learn", "learner", "learning"]
]

model = FastText(
    sentences,
    vector_size=30,
    min_count=1
)

print(model.wv["teachers"][:5])
Worked Example — Start with a Word in a Document and Build a FastText-Style Vector

Document:

D1 = "cat chases mouse"

Focus on the word:

cat
1
Add boundary symbols and create simple character trigrams.
<cat>
subwords: <ca, cat, at>
Real FastText commonly uses multiple n-gram lengths. We use only three pieces so students can calculate the vector by hand.
2
Assume the learned subword vectors are:
<ca = [0.2, 0.4]
cat = [0.6, 0.2]
at> = [0.4, 0.5]
3
Add the subword vectors.
[0.2,0.4] + [0.6,0.2] + [0.4,0.5]
= [1.2, 1.1]
4
Use a simple average for this teaching example.
[1.2,1.1] / 3
≈ [0.400, 0.367]
Illustrative vector for “cat”: [0.400, 0.367]

If the model later sees a related form that shares some of these character pieces, it can reuse subword information instead of depending only on an exact word lookup.

What students should remember: FastText uses subword pieces, so it is especially useful for word forms and morphology.

8. Cosine Similarity

Once text has been converted into vectors, we need a way to compare those vectors.

cosine similarity = (A · B) / (||A|| × ||B||)

For this course, the geometric intuition matters more than memorizing the formula:

  • Vectors pointing in similar directions → higher similarity.
  • Vectors pointing in different directions → lower similarity.

0.95

Very similar

0.55

Moderately related

0.08

Weakly related

Python: cosine similarity
from sklearn.metrics.pairwise import cosine_similarity

score = cosine_similarity(
    [vector_a],
    [vector_b]
)[0, 0]

print(score)
Worked Example — Start with Two Documents and Calculate Cosine Similarity

Documents:

D1 = "cat runs"
D2 = "cat sleeps"
1
Build a shared vocabulary.
Vocabulary = [cat, runs, sleeps]
2
Convert each document to a simple count vector.
D1 = [1, 1, 0]
D2 = [1, 0, 1]
3
Calculate the dot product.
D1 · D2
= (1×1) + (1×0) + (0×1)
= 1
4
Calculate each vector length.
||D1|| = √(1² + 1² + 0²) = √2 ≈ 1.414
||D2|| = √(1² + 0² + 1²) = √2 ≈ 1.414
5
Calculate cosine similarity.
cosine(D1,D2) = 1 / (1.414 × 1.414)
= 1 / 2
= 0.50
Final similarity: 0.50. The documents overlap on “cat”, but each also contains a different word.
What students should remember: cosine similarity is a common way to compare text vectors.

Static embedding

Word2Vec/GloVe usually give “bank” one main learned vector.

Contextual embedding

Transformer models such as BERT generate a token representation that depends on the surrounding sentence.

10. Sentence Embeddings

Sentence embeddings represent an entire sentence or short document as one dense vector.

This makes them very useful for semantic similarity, clustering, retrieval, and search.

🔐
I forgot my password.
0.86
high similarity
similar meaning
🔑
How can I regain access to my account?
0.12
low similarity
📦
My package arrived.

Why this matters

Two sentences can be semantically similar even when they share very few exact words. Sentence embeddings are designed to capture that broader meaning.

Python: Sentence Transformers
from sentence_transformers import SentenceTransformer

model = SentenceTransformer(
    "all-MiniLM-L6-v2"
)

sentences = [
    "I forgot my password.",
    "How can I regain access to my account?"
]

embeddings = model.encode(
    sentences,
    normalize_embeddings=True
)

print(embeddings.shape)

Sentences:

What students should remember: sentence embeddings represent overall meaning, not just individual words.

11. Similarity Search with Questions and Answers

A useful next step is to store question–answer pairs. We compare a new question with the stored questions, rank them by similarity, and return the answers attached to the top matches.

Key idea: we search using the stored questions, but when we retrieve a match, we return both the similar question and its associated answer.

Sort by similarity.
1. Q1 password → 0.994

Main idea: the similarity calculation is performed on the questions. Once the top questions are found, their stored answers come with them.
In a real system, the vectors have hundreds of dimensions. The process is still the same: embed → compare → sort → retrieve top-k Q&A pairs.

11.4 Real Python version

Python: retrieve top 5 similar questions and their answers
import pandas as pd
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity

data = pd.DataFrame({
    "question": [
        "How can I reset my password?",
        "I forgot my account password. What should I do?",
        "How do I change my email address?",
        "Why was I charged twice?",
        "How long does shipping take?",
        "My package has not arrived. What should I do?",
        "How can I recover my account?",
        "How do I update my payment method?",
        "Can I change my password from account settings?",
        "How do I enable two-factor authentication?"
    ],

    "answer": [
        "Go to Account Settings → Security → Reset Password.",
        "Use the Forgot Password link on the sign-in page.",
        "Open Profile Settings and update your email address.",
        "Contact billing support and provide the transaction details.",
        "Standard shipping usually takes 3–5 business days.",
        "Check the tracking page first, then contact shipping support.",
        "Use your recovery email or contact account support.",
        "Open Billing Settings and select Update Payment Method.",
        "Yes. Open Account Settings → Security → Change Password.",
        "Open Security Settings and enable two-factor authentication."
    ]
})

model = SentenceTransformer("all-MiniLM-L6-v2")

question_vectors = model.encode(
    data["question"].tolist(),
    normalize_embeddings=True
)

new_question = (
    "I cannot remember my password. "
    "How do I get back into my account?"
)

query_vector = model.encode(
    [new_question],
    normalize_embeddings=True
)

scores = cosine_similarity(
    query_vector,
    question_vectors
)[0]

data["similarity"] = scores

top_5 = data.sort_values(
    "similarity",
    ascending=False
).head(5)

print(top_5)
What students should remember: embeddings let us retrieve the most similar stored questions. Because every stored question has an answer, the retrieval result can return useful Q&A pairs for the next step.
What could happen next? A later system could use the best answer directly, combine several retrieved answers, or pass the retrieved information to another model. For this module, the important concept is the retrieval step.
