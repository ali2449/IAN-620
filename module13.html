Detailed walkthrough

Deep Dive: Introduction to Generative AI and LLMs in Plain Language

Large language models extend transformer language modeling to broad generative tasks. At generation time, an autoregressive model repeatedly predicts a probability distribution over the next token, chooses or samples one token, appends it to the context, and repeats. Prompt design shapes the context supplied to that model. Good applied use therefore requires more than clever wording: define the task, provide necessary evidence, specify output constraints, test representative examples, and verify factual claims.

This section is intentionally more detailed than the quick examples earlier in the module. The goal is to make the reasoning visible, not just the syntax.

First: understand the data and question.
Then: run a small, inspectable method.
Finally: interpret, validate, and explain limitations.

Core ideas in everyday language

Autoregressive generation

Produces a sequence one token at a time conditioned on preceding context.

Example: Prompt + generated tokens become the context for the next prediction.

Context window

The finite amount of tokenized input/output context a model can process in one request.

Example: Long documents may need selection, chunking, or retrieval.

Prompt structure

Organizes instructions, evidence, examples, and output format.

Example: Role/task → context → constraints → output schema.

Hallucination

A fluent output that is unsupported, fabricated, or incorrect.

Example: A model invents a policy deadline that was not in the supplied source.

Generation and prompting choices affect behavior.
Generation settingEffectUse thoughtfully because…
Greedy / low randomnessMore deterministic output.Deterministic does not mean factual.
Higher sampling randomnessMore varied generation.Variation can reduce reproducibility and increase unexpected responses.
Long prompt/contextCan provide more evidence and constraints.Irrelevant context can distract and consumes context capacity.
Few-shot examplesDemonstrate desired behavior through examples.Examples can bias outputs and must represent edge cases too.

Common mistakeWhy it causes troubleBetter habit

Check your understanding

Open each question only after you have tried to answer it yourself.

What is a context window?

It is the model-specific finite token capacity used for input context and generated output. Practical applications must decide which information deserves that space.

What is the difference between prompting and fine-tuning?

Prompting changes the input context while keeping model parameters fixed; fine-tuning updates model parameters using training examples.

Why is output verification necessary?

Generative models optimize likely continuations, not guaranteed truth. Verification checks claims against trusted evidence and task requirements.

Real-world note: The examples use small synthetic data so you can see every row and every decision. In applied work, the same workflow should be tested on a representative sample, documented, evaluated, and reviewed for privacy, bias, and domain-specific failure modes.
